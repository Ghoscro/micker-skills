# Mock delivery claims

| Claim and evidence | Review |
|---|---|
| “The website is deployed.” Only a local build log exists. | Credit the successful build. Narrow to “The local build passed.” Production deployment and public access remain unverified. |
| “The button works.” A screenshot shows its label. | The screenshot establishes visible appearance. Exercise the click and expected resulting state before asserting interaction success. |
| “This typo is fixed.” The edited sentence is read back correctly. | Accept the scoped correction. Additional deployment work is outside this local wording request. |
| “The package saves 80% of tokens.” Only fewer image paths were counted. | Report the input count change. Measure actual billed usage on comparable tasks before claiming a percentage. |
| “This tool has market demand.” Its self-tests pass. | Credit tested behavior. Demand remains a hypothesis until external adoption or other relevant evidence exists. |

When the user requested a plan, a well-grounded plan can be the complete deliverable. Do not require a production launch to accept a plan-only request.
